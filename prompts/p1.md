# Prompt per Claude Code — pwdv

Uno step per prompt. Non incollarli tutti insieme.

---

## Step 1 — scaffold + tipi chiave

```
Inizializza il progetto Rust `pwdv` come libreria + binario.

File da creare:
- Cargo.toml: dipendenze esattamente come in CLAUDE.md, niente altro
- src/lib.rs: dichiarazione moduli `error`, `key`, `format`, `crypto`
- src/error.rs: enum `VaultError` con thiserror. Varianti: BadMagic, UnsupportedVersion(u8), Truncated, AuthFailed, Kdf(String), Io(std::io::Error)
- src/key.rs: struct `Key32([u8; 32])` con ZeroizeOnDrop, senza Debug/Display/Clone/Copy. Metodi: `random() -> Self` (OsRng), `from_bytes([u8;32]) -> Self`, `as_bytes(&self) -> &[u8; 32]`
- src/format.rs: struct `KdfParams { m_cost: u32, t_cost: u32, p_cost: u32 }` con `Default` ai valori di CLAUDE.md; struct `Header` con tutti i campi della tabella; `Header::parse(&[u8]) -> Result<(Header, &[u8]), VaultError>` che ritorna header e slice del ciphertext; `Header::to_bytes(&self) -> [u8; 130]`; costanti `MAGIC`, `VERSION`, `HEADER_LEN`
- src/crypto.rs: solo firme + `todo!()`, nessuna implementazione

`Header::parse` valida magic, version, lunghezza minima. Nessun panic su input arbitrario.

Verifica: `cargo build`, `cargo clippy -- -D warnings`.
Report: file creati, firme pubbliche.
```

---

## Step 2 — core crittografico

```
Implementa src/crypto.rs. Rispetta le regole AAD di CLAUDE.md alla lettera.

Funzioni pubbliche:
- `derive_kek(password: &[u8], salt: &[u8; 16], params: &KdfParams) -> Result<Key32, VaultError>`
  Argon2id V0x13, output 32 byte, via `hash_password_into`. Nessuna stringa PHC.
- `seal(password: &[u8], plaintext: &[u8], params: KdfParams) -> Result<Vec<u8>, VaultError>`
  Genera salt, dek_nonce, vault_nonce, DEK da OsRng. Costruisce l'header, wrappa la DEK con la KEK, cifra il plaintext con la DEK. Ritorna header || ciphertext.
- `open(password: &[u8], file: &[u8]) -> Result<Zeroizing<Vec<u8>>, VaultError>`
  Parse header, deriva KEK, unwrap DEK, decifra. Qualsiasi fallimento di tag → VaultError::AuthFailed.
- `change_master(old: &[u8], new: &[u8], file: &[u8], params: KdfParams) -> Result<Vec<u8>, VaultError>`
  Unwrap della DEK con la vecchia password, nuovo salt e nuovo dek_nonce, re-wrap con la nuova KEK. vault_nonce e ciphertext devono restare **byte per byte identici**.

L'AAD del vault va costruita in una funzione privata unica usata sia da seal che da open, per evitare divergenze.

Verifica: `cargo test`, `cargo clippy -- -D warnings`.
Report: firme finali, come è costruita ogni AAD, output dei test.
```

## Step 3 — test di sicurezza

```
Crea tests/tamper.rs. Nessun test banale, nessun test che passi per costruzione.

Test richiesti:
1. roundtrip: seal poi open restituisce il plaintext originale
2. password sbagliata → Err(AuthFailed)
3. tamper: per ognuno di questi campi, flippa un bit e verifica Err(AuthFailed):
   ciphertext, tag finale, salt, m_cost, t_cost, p_cost, dek_nonce, wrapped_dek, vault_nonce
   Usa un helper parametrizzato sugli offset, non nove test copiati.
4. version byte alterato → Err(UnsupportedVersion)
5. magic alterato → Err(BadMagic)
6. file troncato a ogni lunghezza da 0 a 130 → sempre Err, mai panic
7. due seal con stessa password e stesso plaintext producono salt, nonce e ciphertext diversi
8. change_master: la vecchia password fallisce, la nuova apre, `file[106..]` identico prima e dopo

Usa parametri Argon2id ridotti (m_cost = 8192, t_cost = 1) solo nei test, per tenere i tempi bassi. Almeno un test deve usare i parametri di default.

Verifica: `cargo test`.
Report: elenco test con esito, tempo totale.
```

## Step 4 — vault store + CLI

```
Aggiungi il livello dati e la CLI.

Dipendenze nuove: serde (derive), serde_json, clap (derive), rpassword.

- src/vault.rs: struct `Entry { name, username, password: String, url: Option<String>, notes: Option<String>, created, modified }`, struct `VaultData { version: u32, entries: Vec<Entry> }`. Serializzazione JSON. `VaultData` non deriva Debug.
- src/store.rs: `load(path, password) -> Result<VaultData>`, `save(path, password, &VaultData) -> Result<()>`.
  save: scrittura atomica (tempfile nella stessa dir, sync_all, rename) + backup `.bak` del file precedente.
- src/main.rs: comandi clap `init`, `add`, `get`, `list`, `rm`, `passwd`, `gen`.
  Password sempre lette con rpassword, mai da argomento CLI. `init` e `passwd` chiedono conferma.
  `gen`: generatore con `rand::rngs::OsRng`, lunghezza default 20, set di caratteri configurabile.
  `list` non stampa mai le password.

Verifica: `cargo test`, `cargo clippy -- -D warnings`, prova manuale del ciclo init → add → get → passwd → get.
Report: comandi implementati, output della prova manuale con le password oscurate.
```
