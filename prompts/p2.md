# Prompt per Claude Code — GUI pwdv

Presuppone step 1-4 completati. Uno step per prompt.

---

## Da aggiungere a CLAUDE.md prima di iniziare

```markdown
## GUI — vincoli

- Framework: `eframe`/`egui` 0.28+. Feature `persistence` **disabilitata**: nessuno stato di widget o memoria egui viene scritto su disco.
- `pwdv-core` non dipende da eframe, egui, arboard o da qualsiasi crate grafico. Dipendenza in una sola direzione: gui → core.
- La derivazione Argon2id non viene mai eseguita sul thread della UI. Thread separato + canale, spinner durante l'attesa.
- Buffer della master password: `String` dedicata, dopo l'invio `zeroize()` e poi `clear()`. Mai solo `clear()`.
- Nessuna struct che contiene password decifrate deriva `Debug`, `Serialize` o `Clone`.
- Nessun segreto in titolo finestra, tooltip, log, messaggi di errore, o nel testo di un widget non mascherato.
- Auto-lock: alla scadenza del timer la DEK e i dati del vault vengono zeroizzati e lo stato torna a `Locked`. Non è sufficiente cambiare schermata.
- Gli errori mostrati all'utente non distinguono password sbagliata da file manomesso.
- Fuori scope, da dichiarare nel README: protezione da screenshot, keylogger, screen recording e clipboard manager di terze parti.
```

## Step 6 — macchina a stati e schermata di unlock

```
Implementa lo scheletro della GUI in crates/pwdv-gui/.

File:
- src/app.rs: enum `AppState { Welcome, Creating, Unlocking, Unlocked(Session), Error(String) }`. Struct `PwdvApp` che implementa `eframe::App`.
  `Session` contiene VaultData e il path. Non deriva Debug/Clone/Serialize.
- src/unlock.rs: schermata di sblocco e schermata di creazione vault.
- src/worker.rs: derivazione KDF fuori dal thread UI.
  `spawn_unlock(path, password) -> Receiver<Result<VaultData, VaultError>>`, idem `spawn_create`.
  La password viene spostata nel thread, zeroizzata lì dopo l'uso. Il thread UI chiama `try_recv()` a ogni frame e richiede un repaint mentre è in attesa.
- src/main.rs: `eframe::run_native`, finestra 1000x680, minimo 720x480, icona placeholder.

Requisiti di comportamento:
- Durante la derivazione: spinner, messaggio "Sblocco in corso", campo password e pulsante disabilitati. La finestra non deve mai bloccarsi: verifica che si possa ancora ridimensionare durante l'attesa.
- Invio con Enter nel campo password.
- Campo password sempre mascherato, senza toggle in questa schermata.
- Se il file non esiste, mostra la schermata di creazione con conferma password e avviso che la master password non è recuperabile.
- Tre tentativi falliti consecutivi: ritardo progressivo prima di riabilitare il pulsante (1s, 2s, 4s). Nessun blocco permanente.

Verifica: `cargo run -p pwdv-gui`, ciclo creazione → chiusura → sblocco.
Report: transizioni di stato implementate, conferma che il KDF gira fuori dal thread UI e come lo hai verificato.
```

## Step 7 — vista principale

```
Implementa la schermata principale in crates/pwdv-gui/src/main_view.rs.

Layout a due pannelli:
- Sinistra (larghezza fissa ~300px, ridimensionabile): campo di ricerca in alto, lista voci sotto, pulsante "Nuova voce" in basso.
- Destra: dettaglio della voce selezionata, oppure stato vuoto.

Lista:
- Ogni riga: nome in evidenza, username in testo secondario. Mai la password.
- Ricerca fuzzy su nome, username e url. Filtro a ogni carattere.
- Ordinamento alfabetico, selezione evidenziata.

Dettaglio:
- Campi nome, username, password, url, note, date di creazione e modifica.
- Password mascherata con toggle di rivelazione che si richiude automaticamente dopo 10 secondi.
- Pulsante copia accanto a username e password.
- Modalità visualizzazione e modifica distinte. In modifica: pulsanti Salva e Annulla, Salva disabilitato se nulla è cambiato.
- Eliminazione: dialog di conferma modale che richiede di digitare il nome della voce.

Stato vuoto (vault senza voci): messaggio e pulsante per creare la prima voce, non un pannello bianco.

Ogni modifica confermata fa un `store::save` immediato. Se il salvataggio fallisce, la modifica resta in memoria e viene mostrato un errore persistente, non un toast che scompare.

Verifica: `cargo run -p pwdv-gui`, ciclo aggiungi → cerca → modifica → elimina, riapertura del vault per confermare la persistenza.
Report: file e funzioni, comportamento su vault vuoto e su vault con 500 voci generate.
```

## Step 8 — sicurezza operativa

```
Implementa i comportamenti di sicurezza in crates/pwdv-gui/src/security.rs.

- Auto-lock: timer di inattività configurabile, default 5 minuti. Qualsiasi input tastiera o mouse nella finestra lo azzera. Alla scadenza: zeroize di DEK e VaultData, drop della Session, stato a Locked. Se ci sono modifiche non salvate, salva prima di bloccare.
- Lock manuale: Ctrl+L e voce di menu.
- Clipboard con arboard: dopo la copia, cancellazione automatica dopo 20 secondi con countdown visibile accanto al pulsante. La cancellazione avviene anche se l'utente copia un'altra voce nel frattempo, e al lock.
- Su Linux arboard perde il contenuto quando il processo rilascia la selezione: gestisci esplicitamente il caso X11/Wayland e documenta il comportamento reale osservato. Se la cancellazione non è garantibile, dichiaralo nella UI invece di fingere che funzioni.
- Un solo posto nel codice può scrivere nel clipboard.

Verifica: test manuali documentati per auto-lock, lock manuale, cancellazione clipboard a scadenza e al lock.
Report: esito di ogni test manuale, e in particolare cosa succede davvero al clipboard sul tuo ambiente.
```

## Step 9 — generatore e rifinitura visiva

```
Due parti.

Generatore (crates/pwdv-gui/src/generator.rs):
- Pannello accessibile dal dettaglio voce e come strumento autonomo.
- Slider lunghezza 8-64 (default 20), toggle per maiuscole, minuscole, cifre, simboli, e opzione "escludi caratteri ambigui" (0OIl1).
- Anteprima live rigenerabile, pulsante per applicare alla voce corrente.
- Entropia in bit calcolata e mostrata. Indicatore di robustezza con zxcvbn, non una soglia inventata sulla lunghezza.
- Generazione sempre da OsRng, senza modulo bias: usa rejection sampling.

Rifinitura visiva:
- Font: carica Inter (o altro font incluso nel binario), non il default di egui.
- Scala di spaziatura coerente (4/8/12/16/24), raggio degli angoli uniforme, un solo colore d'accento.
- Tema chiaro e scuro, default seguendo il sistema, switch manuale.
- Scorciatoie: Ctrl+F ricerca, Ctrl+N nuova voce, Ctrl+C copia password della voce selezionata, frecce per navigare la lista, Esc chiude i dialog, Ctrl+L lock. Schermata di aiuto con l'elenco.
- L'app deve essere usabile interamente da tastiera, con focus sempre visibile.
- Nessun testo troncato senza tooltip, nessun pulsante senza etichetta o icona riconoscibile.

Verifica: `cargo run -p pwdv-gui`, prova completa da sola tastiera.
Report: scorciatoie implementate, scelte di tema, cosa non è raggiungibile da tastiera se qualcosa è rimasto fuori.
```
